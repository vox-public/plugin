# voice-interaction-design

## 판단 순서
대상 고객과 업무의 언어·발화 길이·전화/브라우저 조건을 정하고, 필요한 품질을 충족하는 모델·음성을 제품의 실제 지원 목록에서 고른다. 모델명·가격·지역별 제공 여부를 스킬에 고정하지 않는다.

느림을 사용자가 말을 끝내기 전 끼어듦, 발화 종료 판정 대기, 모델 첫 응답, 외부 도구, 음성 생성/재생으로 나눠 관찰한다. 로그에 없는 구간의 지연을 특정 제공자 탓으로 단정하지 않는다. 전체 지연을 LLM 교체만으로 해결하려 하지 않는다.

## 관찰 가능한 가설
‘더 빠르게’ 대신 ‘고객이 날짜를 생각하는 동안 끼어들지 않되 짧은 답 뒤에는 지체를 줄인다’처럼 목표를 적는다. 한 번에 바꿀 설정은 가설을 판별할 수 있을 만큼 좁힌다. 언어·음성·모델의 지원 관계는 현재 스키마로 확인한다.

브라우저 음성은 대화·끼어들기·지연을, 전화 시험은 전화망·수신/발신·전환을 확인한다. 텍스트 점검으로 음성 품질을 검증했다고 말하지 않는다.

실제 변경과 비교는 [tune-voice-behavior](../tune-voice-behavior/SKILL.md)를 사용한다. 외부 시스템 호출 지연은 [troubleshoot-agent-tool](../troubleshoot-agent-tool/SKILL.md)로 좁힌다.
