# prepare-voice-test

제품 호출에는 [공통 실행 계약](../../references/execution-contract.md)을 적용한다. 내장/외부의 질문·음성·파일 차이는 [호스트 연결](../../references/host-adapters.md)을 따른다. 도구명은 출시 설계이며 연결된 서버의 실제 도구·스키마 확인 후 사용한다.

## 준비
agent·대상 버전·Manual 연결·결과 저장 설정을 확인한다. 자료가 아웃바운드 업무면 합성 사전 정보를 사용해 도입/거절을 시험할 수 있는지 현재 진입 계약을 확인한다. 실고객 데이터나 실제 발신을 기본값으로 쓰지 않는다.

[시험 사례](../../references/voice-test-cases.md)에서 목표에 맞는 정상/변경/오류 상황을 고른다. 시험 대화와 기대 저장값을 짝짓고 브라우저 음성으로 확인할 것과 실제 전화로 확인할 것을 구분한다.

## 진입과 결과
`open_voice_test_session`은 C-196 출시 설계이며 실제 연결·스키마가 제공될 때 사용한다. 내장은 기존 음성 UI, 외부는 해당 agent/버전을 대상으로 하는 로그인 기반 제품 링크를 쓴다. 미구현이면 대상과 시험 안내를 제공하고 음성 진입 불가를 밝힌다. 임의 URL이나 토큰 포함 링크를 만들지 않는다.

사용자가 실제로 시험한 뒤 확인 가능한 callId를 확보하고 `get_call`로 발화·분석 상태·저장 결과를 읽는다. callId가 없으면 추측하지 않는다. 음성 연결 실패와 업무 응답 실패를 구분한다.

## 완료 표시
‘시험 상황 작성’, ‘음성 시험 준비’, ‘실제 대화 수행’, ‘결과 확인’은 다른 단계다. 하나가 완료됐다고 뒤 단계를 완료로 표시하지 않는다. 수정이 필요하면 증거와 함께 해당 전문 스킬로 연결한다.

## AC2 진입 기록 사용

agent·버전·동적 변수와 idempotency_key를 유지한다. ready는 진입 준비이고 call_id는 아직 없다. 사용자 음성 시작 이후 같은 도구·같은 키로 기록을 읽어 실제 call_id를 얻고 get_call로 이어간다. 새 진입을 반복 생성하거나 callId를 사용자에게 매번 찾아오게 하지 않는다. 만료 여부는 expires_at을 따르며 started/ended를 준비 티켓 만료와 혼동하지 않는다. 재호출 간격은 호스트의 상태 확인 정책을 따르고 음성 대기 동안 연속 polling하지 않는다.
