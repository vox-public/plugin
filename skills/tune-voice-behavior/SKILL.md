# tune-voice-behavior

제품 호출에는 [공통 실행 계약](../../references/execution-contract.md)을 적용한다. 내장/외부의 질문·음성·파일 차이는 [호스트 연결](../../references/host-adapters.md)을 따른다. 도구는 연결된 서버가 제공하는 실제 이름과 스키마를 확인한 뒤 사용한다.

## 관찰과 가설
[음성 설계](../voice-interaction-design/SKILL.md)를 읽고 고객의 증상을 재현 상황으로 바꾼다. 현재 설정과 실제 통화의 지원 지표를 읽는다. 지표가 없으면 체감 관찰이라는 한계를 표시하고 임의의 밀리초 수치를 만들지 않는다.

## 변경
`list_models`와 실제 schema로 지원 조합을 확인한다. 사용자가 agent 모델 변경을 요청했을 때만 `list_models(kind=llm)`으로 조회해 [모델 선택 규칙](../build-first-voice-agent/SKILL.md#모델-고르기)을 따른다. 기존 agent 모델은 변경 요청이 없으면 보존한다. 코파일럿을 실행하는 모델과 고객과 대화하는 음성 agent의 모델을 혼동하지 않는다. 가설에 필요한 설정만 `save_agent`로 바꾸고 같은 묶음의 나머지 값을 보존한다. 지원되지 않는 설정명이나 기본값을 추정하지 않는다.

## 음성 모델 만들기
고객이 특정 화자의 목소리를 agent 음성으로 쓰고 싶어 하면 `create_voice_model`을 쓴다. 호출 전에 다음을 확인한다.
- 음원은 공개 HTTPS URL이어야 하고 파일 크기는 6MB 이하다. 로컬 파일은 이 도구로 전달할 수 없으므로 사용자가 `vox voice clone --file <파일>` CLI로 등록하도록 안내한다.
- 화자 본인의 동의를 사용자에게 확인받았고, schema의 동의 확인 필드를 그 사실에 맞게 채운다. 동의가 불분명하면 등록하지 않는다.
- 다른 사람의 목소리나 저작권이 있는 음원은 받지 않는다.
등록 결과로 받은 음성 모델을 `list_models`로 다시 확인한 뒤 `save_agent`로 agent에 적용하며, 적용 뒤에는 고객이 직접 들어 보고 판단하게 한다. 등록 응답이 불명이면 같은 음원을 반복 등록하지 말고 먼저 `list_models`로 확인한다.

## 비교
같은 발화·정정·잠깐의 침묵·끼어들기 상황을 변경 전후에 비교한다. 브라우저와 전화망 시험의 차이를 남긴다. 여러 설정을 한꺼번에 바꿨다면 어떤 설정의 효과인지 분리해 증명하지 못했음을 밝힌다.

설정 재조회 후 실제 시험을 하지 않았다면 ‘변경 저장·재시험 필요’로 끝낸다. 실고객 발신은 이 스킬의 자동 다음 단계가 아니다.

## 마지막 단계: 결정 기록
사용자가 이번 요청에서 앞으로도 지킬 규칙·결정을 말했다면(예: "앞으로", "항상", "다음에도") 저장 후 `save_work_record`의 `decision_set`으로 짧게 기록한다(자동 기록이 OFF이거나 사용자가 기록하지 말라고 했으면 제외).
