# 내장 코파일럿과 외부 호스트

같은 general/mcp/architect 원고와 아래 공통 의미를 사용한다. 호스트 차이만 연결한다. 실제 provider 지원·계정 연결은 J0/J2 검증 전이다.

vox.ai Plugin은 이 원고와 MCP 연결 설정을 배포하는 패키지이고, 실행 호스트가 원고를 읽고 도구를 호출한다. 내장 hosted sandbox는 작업 공간이다. **공통 원고 재사용과 동일한 설치 파일/연결 설정의 무변경 재사용을 구분한다.** 외부 실행은 내장 백엔드·Thread·sandbox에 의존하지 않는다. MCP만 연결했다고 이 스킬이 자동 설치되는 것은 아니다.

| 작업 | 내장 코파일럿 | 외부 Codex·Claude Code |
| --- | --- | --- |
| 제품 실행 | Agents API → service-origin 원격 Agents MCP → API | 호스트 → 원격 Agents MCP → API |
| 인증 | 로그인 조직·사용자를 보존한 위임 credential | OAuth; 자동화 서비스만 조직 API 키 |
| 스킬 공급 | 스킬 전용 묶음, shared references 포함 | 동일 원고 + 호스트별 플러그인/스킬 배포 |
| 질문 | 결과를 바꾸는 선택은 ask_user_choice/UI | 호스트 질문 UI 또는 자연어 |
| 상태 | 화면 agent/페이지는 탐색 힌트; MCP 재조회 | 사용자가 준 대상/조회 결과; MCP 재조회 |
| 음성 | 기존 음성 패널 + 대상/버전/call 참조 | 로그인 기반 제품 시험 링크 + call 조회 |
| 파일 | Thread에 귀속한 sandbox 임시 작업·필요 artifact | 호스트가 허용한 작업 디렉터리·artifact |
| 복귀 | 접근 검사된 Thread 결과/실행 키 참조 | 호스트 대화/작업 기록과 제품 결과 참조 |

## 패키징 경계

`mcp/` 디렉터리에는 MCP **사용 지침**이 들어간다. 내장 스킬 묶음에도 이 지침은 필요하다. 이것과 MCP **연결 설정**을 구분한다. 내장 묶음에 외부 플러그인의 mcp.json/인증 설정을 복제하지 않는다. 직접 service 연결은 호스트 구성에서 관리한다. 원시 키·OAuth refresh token은 스킬/파일에 넣지 않는다.

실행 session/sandbox는 조직×사용자×Thread로 격리한다. 공통 스킬은 고객 데이터 없는 배포 자산이다. 개인 선호와 조직 공유 지식은 별도로 취급하고 오래된 제품 상태는 재조회한다. 기존 session에 새 스킬이 자동 reload된다고 가정하지 않는다.

## 보조 문서 연결

`product-documentation`은 공식 문서 검색 지침이다. 기존 배포의 vox-docs 연결을 유지·검증하거나 호스트 공식 웹 검색으로 대체할 수 있다. Agents 제품 도구 117개와 별도이며 조직 데이터·쓰기 권한을 주지 않는다. 문서 연결 실패만으로 제품 MCP를 중단하지 않는다.

## 제품 모듈: Agents와 향후 desk

현재 모듈 ID `agents`는 스킬 패키지의 설계 식별자이며 실제 MCP 서버명/URL이 아니다. host deployment binding이 연결 식별자와 도구 목록을 매핑한다. 미래 모듈 ID `desk`는 operator 업무용으로 별도 추가한다. 현재는 연결 없음·스킬 없음·실행 불가다.

향후 desk 추가 시 담당 MCP 지침, 실제 도구 원장/스키마, 조직·상담원·통화 주체, 권한, 결과/부작용 의미, 내장/외부 연결 검증을 독립 정의한다. 같은 단어인 ‘발신’, ‘전환’, ‘통화’라도 Agents와 operator 동작을 자동 교환하지 않는다. 다중 연결에서는 모듈+실제 서버 도구 정체성+조직+리소스 종류를 함께 확인한다.

이는 제품별 MCP 계층의 확장 결정이며 이번에 물리 서버·URL·OAuth grant를 몇 개로 나눌지는 정하지 않는다. 사용자 작업 하나 안에서 두 제품을 조합할 필요가 생기면 각 연결의 권한·결과 ID를 따로 유지한다. desk 미연결을 Agents 도구로 우회하지 않는다. 범용 execute_tool 중계나 시나리오별 서버 분할을 추가하지 않는다.

정본: 아키텍처 (제품 계약은 연결된 MCP의 실제 스키마를 확인), 제품 방향 (제품 계약은 연결된 MCP의 실제 스키마를 확인).

## 파일과 업무 요약의 전달

내장은 인증된 첨부 참조와 필요한 MCP 결과를 백엔드가 해당 환경에 복사한 뒤 실제 경로를 공급한다. 모델은 공급된 path/참조를 사용하며 provider ID를 제품 file_key로 바꾸지 않는다. 출력 파일은 지정된 outputs 경로에 저장하고 완료 턴 이후 export 결과를 사용한다. 외부는 호스트 첨부·인증 업로드·MCP resource 등 실제 지원 경로를 사용하며 내장 백엔드에 의존하지 않는다.

목표·가정·결정 출처·완료 참조·다음 행동을 간결한 업무 요약으로 유지한다. 내장은 호스트가 요청한 형식의 checkpoint를 작성할 수 있고, 외부는 자체 대화/작업 기록을 이용한다. 모델이 기록한 ‘완료’는 제품 상태를 증명하거나 새 권한을 부여하지 않는다. 복귀할 때 관련 리소스와 미확인 실행을 다시 확인한다.
