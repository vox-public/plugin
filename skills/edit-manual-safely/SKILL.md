# edit-manual-safely

제품 호출에는 [공통 실행 계약](../../references/execution-contract.md)을 적용한다. 내장/외부의 질문·음성·파일 차이는 [호스트 연결](../../references/host-adapters.md)을 따른다. 도구는 연결된 서버가 제공하는 실제 이름과 스키마를 확인한 뒤 사용한다.

## 피드백·재개 반영 순서
같은 대화의 피드백이든 새 대화의 이어서 작업이든 같은 순서를 따른다.
1. **대상 찾기**: 같은 대화에서 만든 에이전트면 그 `agent_id`를 쓴다. 새 대화면 사용자가 말한 이름·업종으로 `list_agents`를 찾는다. 후보가 둘 이상이면 이름과 수정 시각을 보여 주고 고르게 한다(답을 받을 수 없으면 이름이 정확히 같은 것을 고르고 그 가정을 알린다).
2. **현재 상태 읽기**: `get_agent`, `list_manuals`, 관련 `get_manual`을 읽는다. 새 대화면 사용자에게 한 줄로 요약한다(예: "Single + Manual 4개(예약 접수·단체 예약·직원 연결·영업 안내), 마지막 수정 ○○"). 작업 기록 도구(`get_work_context`)가 있으면 이전 결정도 함께 읽는다. 없으면 에이전트에 저장된 내용이 정본이다.
3. **요청과 대조**: 요청을 현재 본문과 비교한다.
   - 이미 그렇게 돼 있으면 쓰지 않고 "이미 ○○로 돼 있습니다"라고 알린다.
   - 해석이 둘 이상이면(예: "8명 기준"이 8명 초과인지 8명 이상인지) 현재 문구를 보여 주고 한 가지를 제안해 확인받는다. 답을 받을 수 없으면 현재 표현 방식을 유지하는 해석을 고르고 그 가정을 알린다.
   - 요청이 다른 규칙과 부딪히면(예: 프롬프트의 금지와 충돌) 그 점을 먼저 말한다.
4. **범위**: 요청이 가리키는 내용만 바꾼다. 같은 사실이 프롬프트, 다른 Manual, 지식, 통화 결과 항목 설명에도 있으면 함께 바꾸고 그 목록을 알린다. 그 밖의 문장·구조·이름은 바꾸지 않는다.
5. **저장**: 방금 읽은 `expected_head_revision`으로 저장한다. 409면 다시 읽고 같은 의도를 다시 적용한다. 저장 뒤 다시 읽어 바뀐 곳과 [운영 수준 점검](../manual-authoring/SKILL.md) 중 관련 항목을 확인한다.
6. **알리기**: 바꾼 곳마다 한 줄로 알린다: "<위치>: '<전>' → '<후>'". 바꾸지 않은 것이 있으면 이유도 한 줄로 쓴다. 행동이 바뀌는 수정이면 다시 시험할 상황 하나를 덧붙인다.

## 쓰기 전
[get_agent/get_manual의 실제 결과](../explore-agent-context/SKILL.md)에서 대상 Single의 `agent_id`, Manual의 `manual_id`, 현재 `head_revision`, 완전한 원문을 확보한다. 사용자 요청 부분과 보존할 규칙을 구분한다. 다른 agent와의 영향이 의심되면 [영향 범위](../review-shared-impact/SKILL.md)를 먼저 확인한다.

## 본문 편집
긴 문자열은 현재 원문을 파일에서 수정하고 변경 전후를 비교할 수 있다. 동일 문장이 여러 번 나오면 첫 항목을 임의 치환하지 않고 대상 문맥을 고른다. sandbox 파일 편집을 제품 저장으로 말하지 않는다.

Manual `content`는 전체 교체다. 새 본문에서 누락된 도구 참조·종료 규칙·정정 처리를 확인한다. `tool_ids`, `linked_manual_ids` 같은 파생 필드를 임의로 save payload에 넣지 않는다. Agent 설정의 `data.manuals`는 UUID 키를 사용하며 이를 보낼 때 현재 Manual 값을 보존한다. 구체 입력은 [공통 계약과 예제](../../references/workflow-examples.md)를 사용한다.

## 저장과 실패
`save_manual(mode=update)` 또는 해당 `save_agent`에 방금 읽은 `expected_head_revision`을 포함해 저장하고 같은 `agent_id`·`manual_id`를 재조회한다. 저장 성공 뒤 재조회 실패는 ‘저장 응답 성공·확인 미완료’다. `409` conflict면 현재 값을 다시 읽고 사용자 의도를 재적용한다. unknown 쓰기나 재조회 실패 뒤 새 Manual을 만들거나 같은 쓰기를 자동 재실행하지 않는다.

수정이 행동에 영향을 주면 [음성 시험](../prepare-voice-test/SKILL.md)에 재현 상황을 전달한다. 사용자가 원고 수정만 요청했다면 시험 준비/미실행을 분명히 하며 외부 전화는 시작하지 않는다.

## 마지막 단계: 결정 기록
사용자가 이번 요청에서 앞으로도 지킬 규칙·결정을 말했다면(예: "앞으로", "항상", "다음에도") 저장 후 `save_work_record`의 `decision_set`으로 짧게 기록한다(자동 기록이 OFF이거나 사용자가 기록하지 말라고 했으면 제외).
