# ElevenLabs에서 가져온 구조와 변경 이유

기준: elevenlabs/plugin commit `1c5f1de18e1d28a3c84a9aa2146a6a5e9484488c` (플러그인 manifest 0.4.0). 정적 파일 42개를 대상으로 한 설계 이식이다. 원문을 통째 복제하지 않고 업무 구조·작업 분해·복구 패턴을 한국어로 재작성했다. 공급자/고객 내부 정보와 실행 credential은 포함하지 않는다.

## 채택

- general / mcp / architect의 관심사와 유지보수 경계를 분리한다. general은 vox.ai 제품 지식·작성 기준으로 시작한다. ElevenLabs의 SDK 예제를 가짜 vox.ai SDK로 바꾸지 않는다.
- 작은 전문 스킬과 상위 업무 스킬을 조합한다. 관련 단계에서만 읽고 고정 DAG나 별도 agent를 만들지 않는다.
- 실제 ID/상태/결과, 부분 성공 뒤 복귀, 근거로 원인 분류, 실패에서 만든 시험 상황, 외부에서도 독립적으로 사용할 공통 참고 자료를 채택한다.
- 공통 API 계약은 references와 MCP 원장에 두고 여러 스킬에 필드 설명을 복제하지 않는다.

## 이식하지 않은 계약

ElevenLabs의 REST+API key 우회, branch/draft/compile, 실시간 DOM 도구, 자체 code tools, 고객용 test/QA ticket/traffic rollout 강제는 복제하지 않는다. vox.ai의 Single + Manual, 직접 MCP, 기존 API 의미, 직접 음성 시험, 최소 복귀를 보존한다. 번호·트래픽 등 이미 원장에 있는 제품 동작은 요청 시 사용할 수 있지만 모든 수정에 branch나 traffic rollout을 강제하지 않는다.

## 원문 간 충돌 처리

동일 커밋에서 create-simulation-test/fix-agent-qa-ticket은 simulation 수정을 삭제·재생성으로, mock-all-tools/get-agent-ci-green은 PUT 보존 수정으로 설명한다. mock strategy all의 override 적용 여부도 충돌한다. create-webhook-tool의 path/query 배열 설명과 shared reference의 object 설명도 다르다. 어느 쪽을 vox.ai 계약으로 선택하지 않았으며 해당 payload를 모두 이식 대상에서 제외했다. 우리 API 스키마와 실제 호출 검증이 정본이다.

## 출처·배포
